# V1.2 播放稳定性体验

这是开发体验包，未经本轮HomePod真机验收；程序内版本暂保留V1.1，不是正式V1.2。27.2灯效和新HomePod真机适配尚未完成。

先从托盘退出旧程序，完整解压到独立目录。双击 `Start-V1.2-Preview.cmd` 启用时钟对齐发送、采集率补偿、有限卡顿恢复及媒体信息同步；日志应出现“已启用V1.2时钟对齐与采集率补偿试验”。普通 `WinToPod.exe` 与登录启动在“较低缓冲”关闭时使用原策略，可作对照；切换启动入口前须退出托盘。命令行体验参数不保存；设置中的“较低缓冲”会保存，开启时也会启用时钟对齐与采集率补偿。

两种入口共享现有配对、音量和设置；原有自动连接偏好仍生效。采集断供后需要重新积累约100ms输入。PTP失效、失去控制权等保护保持原样。合成波形不等于听感验收。

建议低音量开始，依次验证：单只/立体声双只可听与左右声道；相同音源的低音量、人声、高频音质；暂停30秒再恢复重复5次；静音恢复；iPhone接管后的退让；连续播放1–2小时（有条件到8小时）；兼容播放器声音。记录爆音、变调、起音缺失或断联时刻。

每30秒及停止时的“采集率补偿”行包含补偿ppm、缓冲、丢弃、补零、重新预缓冲和限幅计数。启动/空闲也可能补零，不能单凭计数判断故障。异常后导出诊断。±100/±50/0ppm各8小时为控制器模型检查；真实发送循环与重采样另做短程回环验证。


## 本批入口与验证：音频缓冲实验

preview #10/#11包含已撤销的画面延后方案，不再用于本轮验收。当前使用[preview #13附件](https://github.com/WeiMinal/WinToPod/actions/runs/43885552675/artifacts/14235125600)，构建源码`d199804b908335d62e6111cb6682229272fe0ec8`；preview #12因打包失败没有运行包。外层附件内选择WinToPod-V1.2-preview-win-x64.zip，SHA-256：`6433020269fb67bf2caacb3195d893ee0e9c5911fd11c7d8da7e9b80306d34f0`。完整证据见V1.2-PROGRESS.md顶部。

新版完整解压到空目录，通过Start-V1.2-Preview.cmd启动，设置 → 声音延迟。默认关闭较低缓冲；先以标准模式连接记录，再断开、开启“较低缓冲（实验）”并重连，比较同一音源。音箱返回完整范围时尝试600ms发送提前量，缺项保留标准目标；这不是声学延迟承诺，也未证明适合游戏。开关会保存；普通EXE或登录启动也尊重已保存的开关，关闭后恢复标准目标。新版没有屏幕捕获与全局覆盖窗口。

组合自动补查、曲目/封面/进度及多来源清空仍需验收；详细延迟边界和录制步骤见[AUDIO-LATENCY.md](AUDIO-LATENCY.md)。出现卡顿/无声时关闭实验开关并手动重连，不会自动切档或抢占音箱重试。

## 曲目、封面与进度同步

体验入口新增 `--media-info`：读取Windows已公开的系统媒体会话，将曲名、作者、专辑、封面和进度通过已有加密控制连接发送给本次音箱；仅内存处理，不把媒体内容写入诊断或磁盘。普通EXE不开启此项。接收端未声明对应能力时不发送；同一文本/封面去重，拒绝可选格式后本次不重复尝试。

只选择唯一处于播放状态且明确标记为音乐的系统媒体会话；视频、未知类型不发送曲目封面，已有信息请求清空；暂停、退出、多个媒体会话同时播放或读取失败时请求清空旧信息。没有集成Windows媒体控制的应用无法提供信息；系统混音也可能包含未注册的其他声音，因此这里的曲目不代表对全部音频来源的识别。封面缩放至最长512像素，单张最多1MiB；进度按带时间戳的媒体快照推进。

建议验证单播放器切歌、封面变更、拖动进度、暂停和退出，再验证两个播放器同时播放时的清空。接收端接受请求不等于控制中心一定展示，也不代表Sound Glow已验证。断联/被接管后不补发清空，不向新所有者写入；正常退出由既有TEARDOWN结束本次会话。媒体信息模块不读取家庭设置、不更改播放器播放状态。

# V1.1 验证范围

运行 `tools/Build.ps1` 生成本次检查报告，`tools/Package.py` 在缺少或失败的必要报告时拒绝打包。发布包 `app/VALIDATION.json` 是对应构建的实际记录。

必要检查包括协议/加密/音量核心检查、自动连接策略、视频状态接口、生产采集与音量边界、COM 接口布局、系统输出切换事务和 WinUI 控制器生命周期。采集和输出测试替代设备边界，不对真实系统设置或音箱操作。

V1.1 增加生产音量方法的回环 TCP 回归：回读落后一档后收敛、持续旧值、首次未确认、静音恢复、无效回读、EOF、403 与取消。测试复用真实 RTSP/音量方法，绕过配对、PTP 和音频发送，不能当作完整 AirPlay 推流验证。有效旧值最多回读四次、SET 只发一次；真正的控制失败继续传播。

Windows CI 额外通过根目录启动器打开合成 WinUI 窗口，检查主题资源加载、窗口布局和退出。真实 Windows 应用混音、DPAPI、系统输出写入、多屏 DPI、任务栏图标和滚动条交互，以及正式包的 HomePod 长期播放，仍需实机覆盖；自动窗口检查不等于上述项目已验证。

开发期间已有 HomePod mini 原生立体声对双只发声反馈，不能保证所有固件与音源。V1.1 云端完整推流模拟曾触发既有 PTP 同步/发送调度保护，批量回归未全部通过；本版没有把历史 V1.0 的完整模拟通过统计沿用为新版本结论。模拟脚本保留供后续复现与回归。

中低音量曲线根据试听调整，连续且严格递增，0 静音、100% 为接收端 0 dB；未做声学标定，不承诺感知响度严格线性或完整复刻 iPhone 曲线。无真实浏览器环境时，不能把生命周期替代测试当作 B 站/DRM/完整 MV3 安装实测。

## BASE-01：可观测性与特性固定

以下均为模拟/确定性检查，不代表真机验证。保护阈值、协议配置与默认重连策略未调整。

- `PtpClockTracker.Diagnostics` / `PtpClockEngine.Diagnostics` 返回累计数值快照。原有每 30 秒 PTP 状态行保留原字段并追加：有效来源到包间隔的六个互斥桶（≤150、≤250、≤500、≤1000、≤2000、>2000 ms）、最大间隔、5 ms 规则拒绝次数、最大绝对偏移差、非空样本清零次数、其中的间隔清零次数、观察到的就绪丢失次数、最大有效样本间隔、样本年龄与观测窗口。来源由现有校验选择；倒序软件接收时间不计入到包间隔桶；初始偏移不算突变；没有样本时年龄输出 -1 ms。原生对副成员单列数值序号，停止时再输出快照。
- `RealtimeAudioSession.SendSchedule` 统计每次发送后的落后量；>50、>100、>250 ms 计数为累计且互相包含。每 30 秒和发送结束输出本次/最大落后、计数、协商缓冲样本和发包数。统计复用原保护判断的 `remaining`，不另采时间、不放宽 500 ms 阈值。
- `PcmBuffer.Snapshot` 在同一锁下读取丢帧、补零、缓冲与容量，`Clear` 保留累计计数。Windows 采集/界面接线未在此任务修改。内部时间源默认委托原来的 `Stopwatch` / `Task.Delay`，仅 Checks 可注入假时间。
- `BASE-01｜` 前缀的 16 项检查固定间隔清零、就绪窗口/新鲜度、偏移拒绝计数、发送卡顿及精确阈值边界，并校验快照与统计热路径分配。已有 PTP 突变检查保留；新增测试不使用真实睡眠。

`dotnet run --project src/WinToPod.Checks -c Release --no-build -- --base01-drift` 对 +100、+50、0、-50、-100 ppm 各推进虚拟 8 小时，每小时读取真实发送循环产出的回环 RTP/Sync 包，扣除协商缓冲后输出样本差、毫秒及缓冲占比。PTP 样本直接驱动生产 Tracker，保留其偏移滤波；网络 PTP 收包、鉴权与真实采集不在此装置内。断言只校验装置与理论累计偏差的一致性，不把漂移数值当作产品通过标准。

可用 `python tests/base01_regression.py --output artifacts/base01/run-01 --drift` 保存构建、核心检查及每个现有 Python 模拟场景的原始 stdout/stderr 和退出码；`--dotnet` 可指定 SDK 路径。模拟按顺序运行，soak 固定 `WINTOPOD_SOAK_SECONDS=120`；使用新目录以保留前次证据。短 soak 与虚拟 8 小时均不能替代真实 HomePod 长期播放。

## V1.2 媒体信息检查

新增5组检查：UTF-8/DMAP与长度限制、能力门控/去重/拒绝降级、带时间戳媒体快照推进、真实RTSP发送与清空/日志隐私、403后不再发送。均为模拟/确定性检查，不代表真机验证；Windows系统媒体读取与接收端实际展示、清空及灯效效果仍须实测。普通启动不启用媒体信息，体验入口新增 `--media-info`。

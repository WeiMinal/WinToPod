# V1.2 开发进度

第一批：发送时间轴、短卡顿恢复原型与接收端能力诊断。基于 BASE-01 分支；不修改正式版、README、版本号或发布配置。

## 当前实现

- `AudioSessionOptions.TimingMode = ClockAligned` 在实际发送循环中使用 PTP 固定锚点计算发送期限，保持连续 RTP 时间戳，不反复重新锚定。
- 恢复预算为成员最小协商缓冲的一半，限于 50–1000ms；在发包前及发包后检查。追赶每四包让出 1ms，保留取消、连接所有权、时钟失效保护。预算来自协商值，不代表测得的接收端实际剩余缓冲。
- `Legacy` 仍为默认值。原 BASE-01 检查与断联策略继续原样执行。新原型尚未接入桌面默认播放，原因是仅调整发送时钟会改变采集缓冲的消费速率；下一步需要完成采集速率补偿和音质检查。
- 接收端能力按 `/info` 优先、广播字段补充读取 PTP、曲目文本、封面和进度位；未知型号不被硬编码排除，也不会因版本为 27.2 自动获得能力。此诊断不代表灯效已支持。

## 检查与复现

核心检查新增 8 项，以 `V1.2｜` 开头：四组卡顿/缓冲组合、PTP 过期、预算边界和来源变化、双向漂移短程、新型号能力处理。使用假时间和真实回环 UDP，没有真实睡眠模拟卡顿。

`dotnet run --project src/WinToPod.Checks -c Release -- --v12-drift`：对 ±100、±50、0ppm 各推进虚拟 8h，每小时读取真实 RTP/Sync 包；检查差值不超过一个 352 样本包加 45 样本容差。它不包含真实采集、网络抖动、鉴权和 HomePod 音质验证。

现有完整模拟可运行 `python tests/base01_regression.py --output artifacts/v12/run-01`；其中默认播放仍为 Legacy，不能把这组回归通过当作 ClockAligned 的完整推流验收。

## 下一步与交付门槛

1. 采集速率与音箱时钟间的平滑重采样；覆盖长播、静音、空闲恢复、双声道及音质，接通后才启用新默认路径。
2. 原生对共同时间轴与双成员故障回归；PTP 间隔清零与新鲜度策略仍待独立设计，不能靠无限延长超时掩盖故障。
3. Windows 媒体信息读取、曲目/封面传输与清空生命周期；按实际能力开启，再验证 Sound Glow。先不伪造媒体类型或家庭设置控制接口。
4. 现有 mini + 27.2 真机基线；新 HomePod 的发现、鉴权、双只可听、静音与退让需分别实测。新 Mac 持续连接和四音箱家庭影院仍属协议研究。

所有新策略结果均为模拟检查，不代表真机通过。新体验包须明确实际启用项，不将研究原型包装成已完成适配。

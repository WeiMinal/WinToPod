# V1.2 实现与验证矩阵

2026-11-08。状态对应当前development，不构成正式支持承诺。原生组合是家庭App已建立的立体声对；所有模拟结果都不代表实际出声。设备型号、固件和能力分别判断，未知型号不会被营销名称白名单拒绝。

| 目标 | 当前软件状态 | 验证缺口或后续动作 |
| --- | --- | --- |
| HP-01：现有mini / 27.2 | 既有播放链路及可选时钟对齐、采集补偿 | 当前固件双只可听、30轮状态切换、8h长播待真机 |
| HP-02：新HomePod | 通用发现/鉴权，依实际能力门控；不伪造型号或能力 | mini 2与二代各自单只、同型号原生对需对应硬件；未知型号模拟不等同新硬件通过 |
| HP-03：Sound Glow | 新增可选封面传输，家庭App仍控制灯效 | 默认动画、封面配色、退出行为待实际观察 |
| HP-04：媒体信息 | Windows音乐会话→文本/JPEG/RTP进度；多源/暂停/退出请求清空 | 软件检查与Windows构建记录见PROGRESS；实际媒体应用及接收端显示/清空待实测 |
| HP-05：音乐/视频状态 | 视频与未知类型不发送音乐信息，并请求清空旧信息 | 尚无经验证的协议内容类型控制；不能保证仅凭清空就关闭视频场景灯效 |
| HP-06：顶部触控锁定 | 不操作家庭设置；现有控制/音量路径不变 | 家庭App锁定开关两种状态下回归，不能宣称软件新增锁定接口 |
| HP-07：新Mac持续连接 | 时钟对齐、采集补偿、有限卡顿恢复已实现可选路径 | 尚未证明与Apple新Mac模式相同；真实延迟/空闲恢复需要测量 |
| HP-08：四音箱环绕 | 未实现 | 需要声道分配/协商证据和相应硬件；四只重复立体声不等同环绕 |
| HP-09：能力矩阵 | 本表与接收端能力数值诊断 | 补充逐型号真机结果，不从27.2版本号推断能力 |
| BASE-01：稳定性 | 确定性检查、可选发送与采集闭环；原保护保留 | 新增发现不完整组合自动补查，待真机回归；休眠/网络抖动/实际长播仍待测；PTP保护策略未放宽 |
| BASE-02：视频补偿 | 延续现有浏览器/本地播放器路径 | B站切集/倍速/字幕/画中画待独立改进与浏览器验证 |
| BASE-03：助手交付 | 手动安装；新增弹窗在线/协议/授权/页面反馈及重新检测入口 | 商店分发/更新入口、完整MV3与B站验证待完成；页面无心跳不等同未安装 |
| BASE-04：Mac/Apple TV接收 | 通用发现及既有连接路径 | 无声/鉴权拒绝需相应接收端日志及真机，不能按握手判通过 |
| BASE-05：独立多目标 | 未实现 | 与原生立体声、四音箱环绕分开设计/验收 |
| BASE-06：图标/快捷方式 | 保留既有主题与透明Logo方案 | 静态EXE/固定快捷方式缓存限制仍在；本轮未修改UI |
| BASE-07：全局音画补偿 | 未实现，研究项 | 受保护内容、系统覆盖范围、性能尚未验证 |

发布候选门槛：先收敛P0播放与能力识别，完成可利用媒体链路；可选项没有真机证据时明确标为实验能力。研究项不能以调整超时或伪造握手字段替代实现。本矩阵沿用原规划编号，未删减待办，也不把研究项标成已完成。

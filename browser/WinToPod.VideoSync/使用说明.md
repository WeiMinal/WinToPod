# WinToPod 浏览器音画补偿助手

助手延后网页画面，让画面等待HomePod的音频缓冲；不降低音箱延迟，也不改变网站声音。首次安装后，B站普通视频自动随WinToPod连接启停，无需填写延迟或逐个页面启用。其他网站可在扩展中单独授权。

## 首次安装或更新

1. 完整解压 WinToPod并保留 `app/浏览器音画补偿` 文件夹。打开 edge://extensions 或 chrome://extensions，开启开发人员模式，选择“加载解压缩的扩展”，选中此文件夹。浏览器需要你亲自授权，桌面软件不能静默完成。
2. 安装后打开B站并用WinToPod连接音箱；若安装前页面已打开，正常重载一次页面。旧助手请在扩展管理中重新加载本次文件夹。
3. 播放后等待缓冲。扩展显示“画面自动补偿中”、桌面“设置 → 视频同步”出现实际呈现帧数，才表示延后链路在工作。“音箱已连接”本身只说明音频状态。
4. 音箱断开或WinToPod退出后约一次轮询恢复原画面。其他网站点击“为此网站启用”并授权即可尝试。“停用”只暂停该网站，不会控制或抢占音箱。

## 当前范围

使用WebCodecs的VP8编码队列，最高1920×1080，采样上限约60fps；实际帧率取决于视频、浏览器及设备性能。更高分辨率会缩放，处理会增加CPU或显卡开销。最长5秒画面队列，编码数据上限32MiB，超限恢复原画面并报告不兼容，不把回退当作同步成功。

普通HTTPS网页视频或本机安全上下文可尝试。受保护视频、不可读取的跨域帧、原生控制条、画中画及直接让video元素原生全屏暂不支持；网页播放器的容器全屏可尝试。页面弹幕、DOM字幕和操作反馈尚未随画面一起延后。暂停会排完已有画面；拖动后的新画面等待已排队的音频；切换标签页时恢复原画面，返回后重新缓冲。

建议延迟来自AirPlay协商采样数和本机采集队列年龄估计，没有通过麦克风测量你家音箱的声学延迟。请用口型实测。Windows系统级全局补偿、游戏和通话低延迟尚未实现。

## 本机数据与检查

仅访问127.0.0.1:38765，读取连接与建议延迟，报告固定枚举状态、帧数和延后毫秒数。URL仅在浏览器内判断网站授权，不发给桌面，不保存浏览内容、账号、音视频或按键。无远程服务器、无音箱控制API。停用选择保存在浏览器本地。

20项桌面接口、10项脚本生命周期、9项实际Chromium VP8／合成画面检查通过。自制帧号视频设置2000ms后，读出60—61帧差（30fps），最终合成截图为60帧。仅扩展消息传输被替代。完整MV3安装／权限、B站实站和Windows+HomePod声学同步尚未在当前环境验证。

扩展清单数字版本是浏览器必填字段，不表示WinToPod已形成正式版本。

## V1.2 开发中：状态检测

弹窗每秒刷新主程序在线状态、协议兼容、网站授权和补偿状态；将建议延后、已呈现帧数与最近画面延后分别显示。主程序退出后清掉旧计数；DRM、画中画/原生全屏、跨域、编解码或缓冲限制显示具体原因。内部浏览器页面禁用授权按钮；拒绝授权不注入脚本。
